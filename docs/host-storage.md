# 宿主块存储接入边界

本说明适用于 distro 的 `@lowland/kernel/virtio/block.js` 中的
`blockDevice(storage)`。Linux 文件系统通过 virtio 访问宿主存储；这不是用户程序
直接访问 OPFS 的接口，也不改变当前 `CONFIG_MMU=n` 的地址模型。

## 容量与地址

- `capacity` 的单位是字节，必须是非负 JavaScript 安全整数且为 512 的整数倍；
  不满足要求时，设备创建同步抛出 `RangeError`。
- 容量在创建设备时固定。修改原 storage 对象的 `capacity` 不会扩容设备；当前没有
  在线扩容协议，底层文件也不应在设备运行期间被外部截短。
- Linux 请求中的扇区号以 BigInt 计算字节范围。整个读写请求通过容量检查后，
  才会转换为 Number 并调用存储方法，不会将不精确的超大地址交给后端。
- 请求越界返回 IOERR，且不会调用该请求的任何读写回调。这包括由多个描述符
  组成、只有后半段越界的请求。

## 回调与失败

`read(offset, target)` 和可选的 `write(offset, data)` 可以返回数值或 Promise，
结果表示实际完成的字节数。每个描述符要求完整完成；短读、短写、异常或 Promise
拒绝均使请求以 IOERR 完成。需要处理正常短 I/O 的适配器应自行循环，直到填满或
确认无法继续。没有 `write` 时设备对 Linux 公布为只读。

范围检查不是事务保证。请求可能先完成部分描述符，随后因后端错误失败；已经发生
的写入不会回滚。设备报告失败也不意味着底层存储完全没有改变。底层硬件、浏览器
配额、文件系统和存储适配器的错误仍需由应用或文件系统处理。

只有提供 `flush()` 才会向 Linux 公布 flush 能力。其成功应代表适配器完成了自身
承诺的刷新操作；缺少此方法不意味着写入天然持久。`close()` 失败会传播到机器
关闭结果，调用方不应忽略关闭错误或把它当作保存成功。

## 浏览器 OPFS

`flush()` 对应到句柄 `flush()`。关闭时即使刷新抛错，也会尝试关闭句柄。
页面导航造成的独占锁冲突只做有限重试，其他初始化错误直接暴露。
该重试最多调用打开接口 8 次，退避等待依次为 10、20、40、80、160、320、640 ms；
累计等待 1270 ms 不包含浏览器打开接口自身耗时，也不是硬性总超时。

## 验证范围

NodeFS 绑定节点与所属适配器，并将每个打开句柄绑定到原节点。跨适配器节点返回
EINVAL，节点/句柄错配返回 EBADF；这些检查覆盖读取、写入、句柄元数据、截短、
同步和关闭，目录枚举也验证配对。已经 unlink 或被替换的文件仍可通过原有描述符
访问，不会因身份检查而误转到同路径新文件。宿主回归实际使用两个共享根及同一
适配器的不同文件，检查错误请求被拒绝、原文件数据及描述符仍可用，同时保留
unlink/recreate 和 replacement rename 回归。13 项本机及独立打包测试、类型检查
已通过；这不消除无关宿主进程并发改动目录时的路径竞态，也不等于内核挂载验证。

NodeFS 也在读取缓冲区分配和宿主 I/O 前验证完整范围：偏移、长度及结束位置必须
能用非负 JavaScript 安全整数表示，无效请求返回 EINVAL。回归实际记录宿主文件
read/write 调用，确认拒绝路径没有触发这些调用，随后正常读写、EOF 短读和零长度
读取仍可使用同一描述符。数值检查不是内存配额，也不保证任意合法大小都能分配。

NodeFS 时间戳对 1970 年前的值使用向下取整的秒和非负纳秒余数。设置时间时使用
数字秒字符串，不再经 Date 截断到毫秒，也避免 Node 将负数参数解释为当前时间。
纳秒必须为 [0, 1e9) 内的整数，秒必须可安全表示；无效输入在截短等修改前拒绝。
回归覆盖亚毫秒时间、仅修改 mtime 时保留 atime、1970 年前时间及错误输入。
Node/宿主 API 仍有浮点和平台精度限制，测试按微秒级误差核验亚毫秒值；未指定的
时间目前通过读取再写回保留，不是原子的 UTIME_OMIT，不保证保留纳秒精度或并发
外部修改。这些宿主结果不替代 Linux 挂载端到端验证。

distro `fc006be` 修正 NodeFS 的无变化重命名：相同路径不能跳过源存在、父目录及
路径边界验证；两个名称已指向同一设备和 inode 时，宿主 rename 成功后保留两边
缓存节点，而不是错误地分离目标节点或把源节点改绑到目标。比较使用 lstat，
所以两个不同符号链接即使指向同一目标，仍执行正常替换。真正的宿主 rename
仍会被调用，权限检查不由缓存推断替代。新增四项回归连同原有测试共 17 项，

外部宿主进程并发改名的竞态，不代表 Linux 挂载端到端验证。

### 描述符元数据与 FUSE inode 身份修复

`/proc/self/fd/N` 查询路径。请求绑定原有描述符与会话；不需要 `/proc` 路径，
也不会因为文件已被替换或移除而重新解析同名新文件。2 项宿主协议回归检查

distro `d9021e7` 修正 JavaScript virtio-fs 设备的节点编号分配：FORGET 仍释放

整棵记录树；新后端对象得到新编号，不依据路径把替换文件误认作原 inode。
回收后的裸 nodeid 请求仍返回 ENOENT，必须由正常 LOOKUP 重新建立记录。

必须为 `[0, 1000000000)` 内的整数，否则返回 EINVAL，原文件字节和元数据不变。

### 删除与待提交的文件修改

distro `562d2fa` 让 BrowserFS `unlink` 在命名修改队列内继续等待目标文件的
修改队列，直到先前写入/截短的写流成功 close 或失败后 abort，再删除并分离旧
节点。它持有该文件队列直至分离完成，后续旧句柄写入不会重新打开同路径的新文件。
如果删除本身失败，节点不被分离，两条队列仍释放，原句柄可继续使用或重试删除。

distro `a738ead` 在同一适配器的目录移动期间，为源与目标子树安装临时协调屏障。

成功迁移路径与句柄后再放行；复制失败或目标非法同样释放屏障，不阻塞后续重试。

源/目标路径的 lookup 和涉及它们的祖先 readdir 会等待移动结束。已在途的查询

使用各自队列；祖先目录枚举及同一适配器的命名修改会被推迟，这是保守协调的代价。
