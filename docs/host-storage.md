# 宿主块存储接入边界

本说明适用于 distro 从 `@lowland/kernel` 导出的
`blockDevice(storage)`。Linux 文件系统通过 virtio 访问宿主存储；这不是用户程序
直接访问 OPFS 的接口，也不改变当前 `CONFIG_MMU=n` 的地址模型。

## 容量与地址

- `capacity` 的单位是字节，必须是非负 JavaScript 安全整数且为 512 的整数倍；
  不满足要求时，设备创建同步抛出 `RangeError`。
- 容量在创建设备时固定。修改原 storage 对象的 `capacity` 不会扩容设备；当前没有
  在线扩容协议，底层文件也不应在设备运行期间被外部截短。
- Linux 请求中的扇区号以 BigInt 计算字节范围。整个读写请求通过容量检查后，
  才会转换为 Number 并调用存储方法，不会将不精确的超大地址交给后端。
- 请求越界返回 IOERR，且不会调用该请求的任何读写回调。这包括由多个描述符
  组成、只有后半段越界的请求。

## virtio-fs 设备关闭

distro `cfb3c8c` 修正 `fileSystemDevice` 的关闭排空边界。通用设备层此前已等待
在途队列 handler，但文件系统 handler 仍可能继续发起下一条排队请求并发布迟到
响应。现在关闭时先同步标记停止，不再处理后续请求；当前请求完成或失败后，不再
写响应、完成描述符或发中断，排空后才释放所有句柄并调用 `destroy()`。
迟到成功的 `open()` 仍登记句柄，由最终清理释放，不能因不发布响应而泄漏资源。

FS 后端可选提供同步 `stop()`，在等待在途请求前启动自身的取消机制。没有此方法
仍等待当前请求自然结束；回调抛错也继续排空和释放，并通过设备关闭结果报告失败。
`stop()` 不能释放当前请求仍使用的资源；整个当前请求可包含多个后端方法，仍须
允许它完成清理。最终释放属于 `release`、`releasedir` 和 `destroy`，关闭保持幂等。

16 项新增宿主回归使用实际共享 Wasm memory 和 virtqueue，覆盖 lookup/open 的
成功、失败、无 stop、主动取消及 stop 抛错；检查排空顺序、迟到句柄释放、后续请求
抑制、响应区与描述符字节保持、零中断和重复关闭。全部 188 项内核宿主测试及源码/
测试严格类型检查通过。修改前四项初始回归因缺少停止回调而实际失败。

和拒绝，同时排入下一请求；精确清单从 21 项增至 22 项，8 项报告门禁回归通过。

### FUSE entry 属性失败后的清理

distro `c9e819c` 修正 LOOKUP、MKDIR、SYMLINK 和 CREATE 的回复准备错误路径。
读取/编码属性期间先持有 lookup 引用，防止并发 FORGET 提前收集节点；若属性操作
失败，则撤回本次引用，保留此前已交给 Linux 的引用。后端节点仍存活时，收集并
重新查找协议记录不会改变它的 inode 编号。

CREATE 在后端成功后，还需要 getattr 才能向 Linux 回复 entry 和 fh。此阶段失败
时，新增路径会尝试释放未发布的句柄一次，不把它遗漏到设备关闭之后；释放失败
不替换原始属性错误，也不自动重试该句柄。后端若释放失败，不能保证其资源已经
释放，仍需后端自身的最终回收策略。创建出的文件不会自动删除：这是错误清理，
不是文件系统事务、原子创建回滚或跨后端隔离。

10 项宿主回归通过真实 virtqueue 验证四种 opcode、新旧引用、CREATE 释放失败、
原始 EACCES 保留、后续查找/精确 FORGET 及关闭不重复释放。修改前已实际复现
残留引用及零次句柄释放；修改后全部 198 项内核宿主测试和源码/测试类型检查通过。
独立浏览器套件新增 CREATE 故障与恢复用例，精确清单增至 23 项，8 项报告门禁

[公开 Chromium/Firefox 检查](https://github.com/HighCWu/linux-wasm-builder/actions/runs/39056981685)

### RELEASE 的单次句柄消费

distro `68870f4` 修正 RELEASE/RELEASEDIR 的 fh 生命周期：在调用后端释放前先消费
协议句柄，避免异步释放期间被另一队列重复使用，也避免后端抛错后关机再次清理
同一 fh。原请求仍返回后端错误；重复请求返回 EBADF，释放失败不会使句柄重新有效。
这与后端实际资源是否成功释放是两件事，后端仍负责失败后的最终资源回收。

### DESTROY 的跨队列排空

distro `1fe00a0` 在 FUSE DESTROY 清理前增加请求排空屏障。以前另一队列的 open
尚未结束时，DESTROY 可能先销毁后端，迟到成功的句柄也错过最终清理。现在先进入
destroying 状态，拒绝新普通请求，再等待已开始的后端操作完成，最后释放句柄并
调用 destroy。屏障不等待 DESTROY 自身，避免自等待；正常操作失败由其自身回复
报告，不阻断 DESTROY 后续清理。后端代码调用前就登记请求，以涵盖同步重入通知。

## 回调与失败

`read(offset, target)` 和可选的 `write(offset, data)` 可以返回数值或 Promise，
结果表示实际完成的字节数。每个描述符要求完整完成；短读、短写、异常或 Promise
拒绝均使请求以 IOERR 完成。需要处理正常短 I/O 的适配器应自行循环，直到填满或
确认无法继续。没有 `write` 时设备对 Linux 公布为只读。

范围检查不是事务保证。请求可能先完成部分描述符，随后因后端错误失败；已经发生
的写入不会回滚。设备报告失败也不意味着底层存储完全没有改变。底层硬件、浏览器
配额、文件系统和存储适配器的错误仍需由应用或文件系统处理。

只有提供 `flush()` 才会向 Linux 公布 flush 能力。其成功应代表适配器完成了自身
承诺的刷新操作；缺少此方法不意味着写入天然持久。`close()` 失败会传播到机器
关闭结果，调用方不应忽略关闭错误或把它当作保存成功。

### 关闭时的停止与在途 I/O

distro `b094494` 为 `BlockDeviceStorage` 增加可选同步 `stop()`。设备关闭时先停止
发起新 I/O，再调用 `stop()`，等待已有处理函数真正结束，最后调用 `close()`。
异步存储可在 `stop()` 中启动自己的取消机制，使已发出的 read/write/flush 结束；
不能在这里提前释放仍被它们使用的句柄或缓冲区。最终资源释放仍属于 `close()`。

关闭开始后，即使当前操作随后成功或失败，也不继续同一请求的后续数据描述符、
不处理已排队的下一条请求，不再发布该在途请求的完成。此前完成的写入不回滚。
`stop()` 抛错仍须等待在途处理结束并尝试 `close()`，其错误由设备关闭结果传播。
关闭仍是幂等的，不重复调用停止或资源释放回调。

没有 `stop()` 的已有存储仍兼容：驱动等待当前 I/O 自行结束后关闭，但不会接着
发起下一次 I/O。停止回调不负责强制终止任意 Promise；后端若永不结束且未提供
有效取消机制，关闭仍可能一直等待。此接口只作用于设备关闭，不是 Linux 进程信号、
请求级取消、设备 reset、写入事务或崩溃持久性协议。

### Node 验收启动器的关闭顺序

## 验证范围

NodeFS 绑定节点与所属适配器，并将每个打开句柄绑定到原节点。跨适配器节点返回
EINVAL，节点/句柄错配返回 EBADF；这些检查覆盖读取、写入、句柄元数据、截短、
同步和关闭，目录枚举也验证配对。已经 unlink 或被替换的文件仍可通过原有描述符
访问，不会因身份检查而误转到同路径新文件。宿主回归实际使用两个共享根及同一
适配器的不同文件，检查错误请求被拒绝、原文件数据及描述符仍可用，同时保留
unlink/recreate 和 replacement rename 回归。13 项本机及独立打包测试、类型检查
已通过；这不消除无关宿主进程并发改动目录时的路径竞态，也不等于内核挂载验证。

NodeFS 也在读取缓冲区分配和宿主 I/O 前验证完整范围：偏移、长度及结束位置必须
能用非负 JavaScript 安全整数表示，无效请求返回 EINVAL。回归实际记录宿主文件
read/write 调用，确认拒绝路径没有触发这些调用，随后正常读写、EOF 短读和零长度
读取仍可使用同一描述符。数值检查不是内存配额，也不保证任意合法大小都能分配。

NodeFS 时间戳对 1970 年前的值使用向下取整的秒和非负纳秒余数。设置时间时使用
数字秒字符串，不再经 Date 截断到毫秒，也避免 Node 将负数参数解释为当前时间。
纳秒必须为 [0, 1e9) 内的整数，秒必须可安全表示；无效输入在截短等修改前拒绝。
回归覆盖亚毫秒时间、仅修改 mtime 时保留 atime、1970 年前时间及错误输入。
Node/宿主 API 仍有浮点和平台精度限制，测试按微秒级误差核验亚毫秒值；未指定的
时间目前通过读取再写回保留，不是原子的 UTIME_OMIT，不保证保留纳秒精度或并发
外部修改。这些宿主结果不替代 Linux 挂载端到端验证。

### 删除与待提交的文件修改

distro `562d2fa` 让 BrowserFS `unlink` 在命名修改队列内继续等待目标文件的

### 目录移动与子树协调

distro `a738ead` 在同一适配器的目录移动期间，为源与目标子树安装临时协调屏障。
复制前等待已缓存后代节点的修改队列结束；屏障安装后发起的写入、截短、同步及
合成元数据修改在节点队列之外等待，避免移动等待修改、修改又等待移动的循环。
成功迁移路径与句柄后再放行；复制失败或目标非法同样释放屏障，不阻塞后续重试。
