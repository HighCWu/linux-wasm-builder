# 宿主块存储接入边界

本说明适用于 distro 的 `@lowland/kernel/virtio/block.js` 中的
`blockDevice(storage)`。Linux 文件系统通过 virtio 访问宿主存储；这不是用户程序
直接访问 OPFS 的接口，也不改变当前 `CONFIG_MMU=n` 的地址模型。

## 容量与地址

- `capacity` 的单位是字节，必须是非负 JavaScript 安全整数且为 512 的整数倍；
  不满足要求时，设备创建同步抛出 `RangeError`。
- 容量在创建设备时固定。修改原 storage 对象的 `capacity` 不会扩容设备；当前没有
  在线扩容协议，底层文件也不应在设备运行期间被外部截短。
- Linux 请求中的扇区号以 BigInt 计算字节范围。整个读写请求通过容量检查后，
  才会转换为 Number 并调用存储方法，不会将不精确的超大地址交给后端。
- 请求越界返回 IOERR，且不会调用该请求的任何读写回调。这包括由多个描述符
  组成、只有后半段越界的请求。

## 回调与失败

`read(offset, target)` 和可选的 `write(offset, data)` 可以返回数值或 Promise，
结果表示实际完成的字节数。每个描述符要求完整完成；短读、短写、异常或 Promise
拒绝均使请求以 IOERR 完成。需要处理正常短 I/O 的适配器应自行循环，直到填满或
确认无法继续。没有 `write` 时设备对 Linux 公布为只读。

范围检查不是事务保证。请求可能先完成部分描述符，随后因后端错误失败；已经发生
的写入不会回滚。设备报告失败也不意味着底层存储完全没有改变。底层硬件、浏览器
配额、文件系统和存储适配器的错误仍需由应用或文件系统处理。

只有提供 `flush()` 才会向 Linux 公布 flush 能力。其成功应代表适配器完成了自身
承诺的刷新操作；缺少此方法不意味着写入天然持久。`close()` 失败会传播到机器
关闭结果，调用方不应忽略关闭错误或把它当作保存成功。

## 浏览器 OPFS

现有站点适配器在专用 Worker 中使用同步访问句柄，循环处理短读写，并将设备
`flush()` 对应到句柄 `flush()`。关闭时即使刷新抛错，也会尝试关闭句柄。
页面导航造成的独占锁冲突只做有限重试，其他初始化错误直接暴露。
该重试最多调用打开接口 8 次，退避等待依次为 10、20、40、80、160、320、640 ms；
累计等待 1270 ms 不包含浏览器打开接口自身耗时，也不是硬性总超时。
宿主测试分别覆盖恢复成功、持续锁冲突耗尽，以及权限/配额等非锁错误不重试。
短读写回归还验证缓冲区和文件偏移同步推进、零进展停止及空操作不访问句柄。

指定容量时先校验，再截短文件；初始化失败会尝试关闭已取得的独占句柄，并保留
原始错误。宿主测试覆盖这些失败路径；“失败 Worker 未被终止时重新打开同一文件，
并验证原内容未改变”的回归已在 Chromium 和 Firefox 独立任务
[38890570648](https://github.com/HighCWu/linux-wasm-builder/actions/runs/38890570648)
实际通过（每个浏览器各 1 项执行、零跳过、零重试，distro `dca1a90`）。该任务
直接打包真实 Worker，不启动 Linux；不能据此宣称 Linux 文件系统持久性、
WebKit 或所有浏览器版本已验证。

## 验证范围

NodeFS 绑定节点与所属适配器，并将每个打开句柄绑定到原节点。跨适配器节点返回
EINVAL，节点/句柄错配返回 EBADF；这些检查覆盖读取、写入、句柄元数据、截短、
同步和关闭，目录枚举也验证配对。已经 unlink 或被替换的文件仍可通过原有描述符
访问，不会因身份检查而误转到同路径新文件。宿主回归实际使用两个共享根及同一
适配器的不同文件，检查错误请求被拒绝、原文件数据及描述符仍可用，同时保留
unlink/recreate 和 replacement rename 回归。12 项本机及独立打包测试、类型检查
已通过；这不消除无关宿主进程并发改动目录时的路径竞态，也不等于内核挂载验证。

NodeFS 也在读取缓冲区分配和宿主 I/O 前验证完整范围：偏移、长度及结束位置必须
能用非负 JavaScript 安全整数表示，无效请求返回 EINVAL。回归实际记录宿主文件
read/write 调用，确认拒绝路径没有触发这些调用，随后正常读写、EOF 短读和零长度
读取仍可使用同一描述符。数值检查不是内存配额，也不保证任意合法大小都能分配。

BrowserFS 在读取文件或创建写流前检查完整 I/O 范围：偏移和长度必须非负且能由
JavaScript 安全整数精确表示，结束位置也不得溢出。无效范围返回 EINVAL，而不是
交给 Blob 切片截断或先创建写流；有效的越过 EOF 读取仍返回短读或空数据。
宿主回归覆盖负数、小数、非有限长度与安全整数边界；浏览器套件另检查真实 OPFS
文件保持原内容且无效请求不触发读取或创建写流。
[38915070575](https://github.com/HighCWu/linux-wasm-builder/actions/runs/38915070575)
已在 Chromium/Firefox 通过：两种浏览器各执行 11 项指定测试，零跳过、零重试，
对应 distro `52deea8`。该测试直接调用目录共享适配器，不启动 Linux。

BrowserFS 的 `flush` / `fsync` 会加入当前节点的修改队列，等待先前排队的写入和
截短操作结束；写流的 `close` 完成前不能提前确认同步成功。该排序约束覆盖通过
同一适配器发出的操作。目录共享使用的浏览器 API 没有额外的物理介质刷盘接口，
因此这里保证提交顺序，不把它表述为操作系统断电后的持久性保证。
该同步排序已在
[38912312816](https://github.com/HighCWu/linux-wasm-builder/actions/runs/38912312816)
通过真实 Chromium/Firefox 验证：延迟真实 OPFS 写流的 close，确认 flush/fsync
仍在等待、提交前读取旧内容，释放 close 后同步调用完成并读取新内容。两种浏览器
各 9 项指定测试全部通过，零跳过、零重试（distro `94ef014`）。

BrowserFS 目录共享适配器也已在 Chromium/Firefox 的
[38911626702](https://github.com/HighCWu/linux-wasm-builder/actions/runs/38911626702)
验证失败写入中止：使用真实 OPFS 文件与写流，在 write/truncate 已执行后注入配额
错误，要求返回 ENOSPC、调用 abort 而不调用 close、原始文件字节保留，随后同一文件
可重新成功写入。两种浏览器各 8 项指定测试全部通过，零跳过、零重试；此项测试
直接执行 distro `5ba05f2` 的目录适配器，不启动 Linux，不覆盖 ext4 或崩溃恢复。
测试包装写流方法以注入操作失败，文件内容和流的提交/中止行为由浏览器自身实现。

普通文件重命名也会加入源节点的修改队列：先等先前写入提交，再复制内容，并在
完成路径与句柄迁移后释放队列。这样先前已经提交的写入不会因为复制旧快照而丢失，
原有打开句柄随后操作迁移后的文件。目录树的并发移动及其他适配器的写入不在该
源文件队列的协调范围内；便携浏览器 API 的复制加删除仍不提供原子重命名。
这一行为已在
[38913323047](https://github.com/HighCWu/linux-wasm-builder/actions/runs/38913323047)
通过 Chromium/Firefox 验证：延迟源写流提交，确认重命名尚未取得源快照；提交后
核对目标内容，再使用原打开句柄写入并核对迁移后的文件。两种浏览器各 10 项指定
测试全部通过，零跳过、零重试（distro `0860502`），测试直接使用真实 OPFS。

宿主回归通过真实 virtqueue 描述符验证范围拒绝、I/O 异常后的后续请求，以及
完成长度只计设备写回的数据和状态字节。这些测试不启动 Linux，也不证明 ext4
或 OPFS 的端到端持久性。浏览器启动测试、文件系统挂载测试与崩溃恢复测试应分别
记录结果，不能互相替代。
