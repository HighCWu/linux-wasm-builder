# Fetch 网络适配边界

`hostFetchNetwork` 将 Linux 程序发出的明文 HTTP/1 请求转换为宿主提供的 HTTPS
Fetch 请求，每个 TCP 连接只处理一次交换。它不是浏览器的原始 TCP 代理，也不绕过
CORS、浏览器网络策略或目标服务的访问控制。调用方必须显式提供 Fetch 回调；
适配器不隐式调用全局 `fetch`。

## 请求与响应

- 请求必须有且只有一个合法 Host，并使用严格 CRLF 分隔；目标不能改变所指定的源。
- CONNECT 和协议升级返回 501；不支持的 Expect 返回 417；无效请求返回 400。
- 转换后的请求使用 `credentials: omit`、`redirect: manual` 和
  `referrerPolicy: no-referrer`。自定义回调若重新构建请求，应自行保留所需策略。
- Fetch 失败在尚未发送最终响应时返回 502。浏览器返回不可见状态的响应也不能当成
  普通 HTTP 成功响应转发。响应开始后的流错误终止交换，不追加第二个 HTTP 响应。
- 响应按下游背压读取；HEAD 不转发响应体，但仍取消回调返回的未使用流。

请求体先检测浏览器是否真正支持流式 `Request`，不依赖 User-Agent。支持时继续流式
传输；不支持时先收集正文再创建 Request，默认最多 16 MiB，可通过
`maxBufferedRequestBytes` 调整为非负安全整数。超限返回 413，不调用 Fetch 回调。
回退路径若从 Content-Length 已知超限，会在发送 `100 Continue` 和读取正文前拒绝；
chunked 正文则在解码收集过程中累计检查。支持流式上传的路径不受该缓冲预算限制。
该限制只作用于缓冲回退。收集器使用按需倍增、容量不超过正文上限的连续缓冲区，
不为每个输入分块保留对象；空分块不增加存储。扩容与最终裁剪仍可能暂时持有两份
缓冲区，浏览器 Request 也可能复制正文，因此正文上限不是进程内存上限。
回退修复源于 Firefox 将 ReadableStream 静默字符串化的问题。

## 输入分块所有权

HTTP ByteReader 现会在首次保留输入分块时复制其字节；与已有残余合并时也使用
自己的缓冲区。来源在下一次 pull 复用 slab，不会再改写请求行、头部残余或已经
交付的正文视图。复制使用 Uint8Array 构造器，避免 Node Buffer 的 slice 仍为
共享视图。来源仍必须保证分块交付时的字节有效：生产者若在读取器有机会接收前
就提前覆写已排队的同一数组，适配器无法恢复已经丢失的数据。

代价是原先直接保留输入视图的路径每个非空分块多一次复制；不因此宣称零复制，
也没有据宿主测试声称目标端吞吐提升。正文继续流式传递，不为此收集整个消息。
distro `c7d2641` 的 4 项宿主回归检查普通数组与 Node Buffer 复用、定长和 chunked
消息跨头部/正文的完整性；前三个初始场景在修复前已复现字节或请求行被改写。
加入已有 HTTP 性质测试及 Fetch 生命周期回归后合计 37 项通过，类型检查通过。
Chromium/Firefox 的分片 POST 用例扩为独立分块与复用 slab 两种来源，各自覆盖
定长及 chunked，共核对 4 次真实 Request 转换；浏览器结果待 CI 验证。仍不访问
外部服务器或运行 Linux 应用，既有上传通过记录不覆盖这项后续修改。

## 取消与所有权

连接取消会传播到交给回调的 `Request.signal`，并取消适配器已持有的响应读取器。
已取消的连接不会再调用 Fetch 回调；取消后才返回的响应也会清理，不向已关闭连接
发送回复。结束时释放请求、响应及输出流的锁；响应流清理失败不覆盖原始写入错误。

自定义回调应遵守 `Request.signal`，包括它启动的额外请求和后台工作。适配器不能
强制终止任意 JavaScript 回调。适配器会在取消时停止等待回调、释放连接流锁，并
清理后来返回的响应；回调自身启动且不响应取消的后台工作仍可能继续。
取消也不能撤销远端已经处理的 POST 或其他写操作。

## 验证范围

轻量 CI 的 `host-fetch-lifecycle.test.ts` 直接执行真实适配器，覆盖 HEAD 清理、
响应头/响应体写入失败、读取期间取消、迟到响应，以及调用前已取消的请求。
这些宿主流测试不启动 Linux，不等于浏览器 CORS、外部网络访问或 Linux 应用端到端
检查通过。涉及实际平台网络策略时，仍须分别进行浏览器与 Linux 程序集成验证。

或重试。该网络用例使用自定义响应流，不访问外部服务器，也不证明 CORS 或 Linux
